# This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.
<!-- END:nextjs-agent-rules -->



1. General Ground Rules
   Tech stack: Next.js 16 App Router, ReactFlow, next-intl, Tailwind, ShadCN/UI.
   Text rules: All display text must be stored in locale files. Do not hardcode Chinese or English text. Translation keys must follow the `module:feature` format.
   Naming rules: Files and directories use lowercase kebab-case. Components use PascalCase. Variables and functions use camelCase. Constants use uppercase snake_case.
   Code rules: TypeScript must be fully typed, with no `any`, no dead code, and no illegal cross-directory references. Exceptions must be caught.
   Components must prefer the `shadcn/ui` component library first.
2. Directory Boundary Rules (Mandatory)
   Business logic may only operate under `projects/[project-id]/*`. Reading or writing system directories or other project directories is forbidden.
   Do not use absolute paths, illegal parent-directory traversal, or unauthorized cross-module access.
   All file operations must go through encapsulated services. Components must not call `fs` directly.
3. ReactFlow Canvas Rules
   Node storage: Only persist `id`, `type`, `position`, and `data`. The structure must be serializable. Do not store DOM nodes, functions, or absolute paths.
   Canvas file: Always save to `projects/[id]/flow.json`, with automatic loading and automatic saving.
   Node types: Only `command-node` and `result-node` are allowed. Data must follow a unified schema.
   State management: Canvas state must be centrally managed. Do not scatter or overuse state inside components.
4. next-intl Internationalization Rules
   Locale files live in `messages/[language].json`. Shared text goes in `common.json`; other JSON files are named after their page modules.
   Pages and components must consistently use `useTranslations`. Do not duplicate translation keys.
   Any newly added copy must be written to the corresponding locale files at the same time, with no missing translations.
5. Local File Read/Write Rules
   Reads and writes must include exception handling and path validation. Do not throw unhandled errors.
   Do not overwrite or delete files that were not generated by the project. Keep local file operations safe.
6. Trae Production-Grade Self-Check
   Add comments where the code needs clarification.
   
   Optimize code to avoid duplicate or redundant logic.
   No cross-directory violations.
   No hardcoded text; all text must go through i18n.
   Complete typing, no `any`, and no redundant code.
   File reads and writes are safe, and exceptions are catchable.
   ReactFlow nodes are serializable and persistable.
   Styles are locally scoped and do not pollute the global scope.
